## Context
Top-AMS Web 页面运行在资源受限的 ESP32-C3 上，现有页面通过 `/ws` 获取配置与运行状态。顶部状态栏已经分别表示浏览器到 ESP32 的 WebSocket 状态和 ESP32 到打印机的 MQTT 状态，但前者只显示“ESP32”，不能说明设备当前的 Wi-Fi 环境。

界面主要由正在安装、调试或排查打印机局域网连接的用户查看。网络信息应像设备仪表一样一眼可读，并继续使用现有页面的浅灰设备面板、蓝色信息色、绿色在线色、琥珀色警告和红色故障语义。

## Goals / Non-Goals
- Goals:
  - 低开销地提供当前连接状态、SSID、IP 和 RSSI。
  - 在现有顶部状态栏中清晰表达信号质量和网络身份。
  - 对首次加载、断开和不可用数据提供可信的降级状态。
- Non-Goals:
  - 不增加 Wi-Fi 扫描、切换网络或重新配网能力。
  - 不显示或传输 Wi-Fi 密码。
  - 不改变 MQTT 状态和现有控制协议。

## UI Direction
- Domain concepts: 无线接入点、射频信号、局域网节点、设备地址、控制器链路、打印机工作间。
- Color world: PCB 深灰、设备外壳白、局域网蓝、在线绿、弱信号琥珀、断链红；全部映射到页面现有语义色，不引入装饰性新颜色。
- Signature: 使用分段式 Wi-Fi 信号阶梯与 SSID/IP 组合成一个“设备网络坐标”，区别于通用的圆点状态卡。
- Rejected defaults:
  - 不新增占空间的指标卡，改为扩展已有顶栏设备状态。
  - 不只用颜色表达强弱，改为图形、文字等级和 dBm 同时表达。
  - 不把 SSID/IP 塞进提示框，改为保持可见并在窄屏自然换行或截断。

### Component checkpoint
- Intent: 帮助用户在打印机旁快速确认 ESP32 连到了哪里、地址是什么、信号是否可能导致掉线；感受应像紧凑可靠的设备仪表。
- Palette: 继承现有蓝/绿/琥珀/红语义，分别表达信息、正常、弱信号和断开。
- Depth: 继承状态栏的轻边框与浅阴影，不增加新的悬浮层。
- Surfaces: 使用现有白色状态栏和页面灰色基底，网络信息不创建独立卡片。
- Typography: 继承现有中文系统字体；SSID 为主要文本，IP 与 dBm 使用等宽数字特性作为设备数据。
- Spacing: 继承现有 4px 倍数与状态项 8px 间距。

## Decisions
### Decision: 使用现有 WebSocket 的只读消息结构
Wi-Fi 状态沿用 `data` 数组，每项使用独立名称：

- `wifi_connected`: 布尔值
- `wifi_ssid`: 字符串；未连接时为空
- `wifi_ip`: 字符串；未取得有效地址时为空
- `wifi_rssi`: 整数 dBm；无有效值时使用 `null`

这些字段不注册为可写配置，也不持久化到 NVS。前端只使用 `textContent` 写入 SSID 和 IP，避免 SSID 中的特殊字符被解析为 HTML。

### Decision: 首连推送，加前端定时按需请求
服务端在 `WS_EVT_CONNECT` 时仅向新客户端发送一份 Wi-Fi 状态。Web 页面在 WebSocket 打开期间每 5 秒发送 `get_wifi_status` 只读动作，服务端只回复发起请求的客户端。WebSocket 关闭时停止定时器并立即将状态标记为不可用。

该方案不新增常驻固件任务；没有 Web 客户端时不会产生周期采集或网络消息，多客户端也不会互相触发重复广播。

### Decision: RSSI 同时显示数值和等级
前端根据 RSSI 映射四档信号：

- `>= -55 dBm`: 强
- `-56` 至 `-67 dBm`: 良好
- `-68` 至 `-75 dBm`: 一般
- `< -75 dBm`: 弱

等级用于快速识别，原始 dBm 用于排障；断开或无有效 RSSI 时不显示虚构的零值。

### Decision: 扩展现有顶部设备状态
桌面端按“信号图形 / SSID / IP / 等级与 dBm”组织，MQTT 状态仍位于另一侧。窄屏允许状态栏换行，SSID 使用安全截断，IP 与 dBm 保持完整可辨认。加载中、在线、弱信号、断开和不可用均同时使用文本与图形表达，不依赖颜色作为唯一信号。

## Risks / Trade-offs
- 5 秒刷新不是逐毫秒实时，但足以观察无线信号变化，并显著降低消息与渲染开销。
- Wi-Fi 真正断开时浏览器通常会先失去 WebSocket，无法收到固件断开快照；前端的 WebSocket `close/error` 状态负责可靠降级。
- 较长 SSID 可能挤占顶栏空间；通过最大宽度、文本截断和移动端换行缓解。

## Verification
- 静态验证 WebSocket JSON 中四个字段的类型与空值行为。
- 使用前端运行时夹具覆盖 RSSI 阈值、特殊字符 SSID、首次加载和 WebSocket 关闭。
- 生成 4/6/8 通道 Web 资源，确认新增状态区与通道数量无关。
- 在实际硬件上验证 RSSI 变化、IP/SSID 准确性以及重新连接后的恢复显示。
