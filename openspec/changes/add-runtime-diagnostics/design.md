## Context
Top-AMS 运行在资源受限的 ESP32-C3 上，现有日志分别散落在串口和单条 WebSocket 文本中，MQTT 状态也不能表达最近收包、自动重连和错误原因。诊断能力必须有固定内存上限，且不能因 Flash 写入或大 JSON 消息干扰换料控制。

界面面向正在打印机旁安装、调试或远程协助排障的用户。信息应像紧凑设备仪表：先判断设备和链路健康度，再查看 Top-AMS 专属换料路径，最后下钻到事件流。

## Goals / Non-Goals
- Goals:
  - 以固定 RAM 成本提供本次启动期间的设备、链路和事件上下文。
  - 明确显示最近一次自动换料的当前阶段、结果和超时位置。
  - 保持现有控制协议和实时控制行为不变。
- Non-Goals:
  - 不持久化日志，不生成综合诊断包。
  - 不抓取完整 MQTT 正文，不增加电机自检。
  - 不启用 Core Dump、任务运行统计或新增第三方依赖。

## UI Direction
- Domain concepts: 耗材通道、料线路径、退料、退线、加热、进线、恢复、微动、小绿点、MQTT 心跳。
- Color world: PCB 深灰、设备外壳白、链路蓝、在线绿、等待琥珀、故障红；沿用现有页面语义色。
- Signature: 六节点“换料链路”以料线路径连接阶段，桌面横向、移动端纵向，并把当前料路进度而非通用指标卡作为视觉中心。
- Rejected defaults:
  - 通用指标卡网格改为按设备、网络和打印机链路分组的紧凑仪表。
  - 无尽终端改为可筛选的结构化事件流。
  - 仅用颜色表示状态改为节点形状、状态文字和颜色共同表达。

### Component checkpoint
- Intent: 帮助用户在一分钟内定位是设备资源、网络/MQTT 还是换料阶段出错；界面应紧凑、可信且像设备维护面板。
- Palette: 继承现有蓝/绿/琥珀/红语义，只在状态发生变化时使用颜色。
- Depth: 使用轻边框和细微表面明度变化，不增加浮夸阴影。
- Surfaces: 页面灰底、白色诊断分区、浅灰数据内嵌区组成三级表面。
- Typography: 中文系统字体负责说明，等宽字体和表格数字负责版本、时长、状态码及日志。
- Spacing: 以 4px 为基础单位，分区和控件使用现有 8/12/16/24px 节奏。

## Decisions
### Decision: 固定容量结构化事件
固件 SHALL 使用 64 条固定数组作为环形日志。每条记录包含递增序号、设备启动毫秒、级别、模块、事件码和最多 112 字节的 UTF-8 消息。覆盖旧记录时累计覆盖计数；清空仅重置内容与覆盖计数，不重置递增序号。

日志写入和快照复制使用短时互斥，序列化和 WebSocket 发送必须在锁外完成。历史日志每批最多发送 16 条，避免一次构造过大的 JSON。

### Decision: 使用带类型的独立 WebSocket 消息
诊断消息使用顶层 `type` 和 `payload`，不复用现有 `data[]` 配置数组：
- `diagnostics_snapshot`
- `diagnostics_log_batch`
- `diagnostics_event`
- `filament_timeline`
- `diagnostics_log_reset`

客户端使用 `get_diagnostics_snapshot` 获取当前快照，使用 `clear_diagnostic_logs` 全局清空日志。连接建立时服务端向该客户端发送快照、时间轴和分批日志；事件和时间轴转换实时广播。

`diagnostics_log_reset` 携带 `cleared_through_seq` 清空水位。客户端只删除不大于该序号的设备事件，因此即使清空与其他任务的新日志并发，也不会把清空后已先到达浏览器的事件误删。

### Decision: MQTT 健康度区分传输状态与数据陈旧
MQTT 回调维护传输状态、最近收包时间、自动重连次数和最近错误。连接仍存在但超过 8 秒未收包时单独标记 `stale`；只在进入和退出 stale 状态时写日志，避免重复警告。

### Decision: 时间轴只描述自动换料
时间轴固定为 `trigger`、`unload`、`retract`、`heat`、`feed`、`resume`。阶段状态为 `pending`、`running`、`success`、`skipped`、`warning`、`error` 或 `not_reached`。正常、跳过、继续执行的超时和终止流程的错误均在实际分支处更新；手动上料只进入事件日志和设备快照。

“恢复成功”只表示 MQTT 发布调用被接受。最近超时点在本次启动期间持续保留，直到被新的超时覆盖或设备重启。

## Risks / Trade-offs
- 固定消息长度会截断极长文本；截断必须停在完整 UTF-8 码点，保证 JSON 可解析。
- 64 条历史不会覆盖长时间运行的全部信息，但固定约 8–10 KB RAM，避免不可控增长。
- MQTT stale 的 8 秒阈值沿用现有判断语义；它只表示数据新鲜度，不等价于 TCP 已断开。

## Verification
- 验证环形覆盖、清空、分批、UTF-8 截断和多任务并发。
- 验证设备快照的空值、MQTT 状态转换和多个 WebSocket 客户端。
- 覆盖自动换料正常、跳过、警告超时和终止错误分支。
- 生成并检查 4/6/8 通道 Web 资源，在桌面和窄屏验证诊断页面。
- 检查串口、WebSocket 和下载文本不包含敏感配置或完整 MQTT 正文。
