# Design: A1 mini 闭环耗材流程

## Context
Top-AMS 同时观察打印机 MQTT 状态、打印机耗材传感器和本机微动输入，并通过 MQTT G-code 与多路直流电机改变同一条耗材料路。现有实现把这些异步信号用固定延时串联，且多个任务可直接驱动 GPIO。修复必须把“打印机接受命令”“打印机执行到某一步”“Top-AMS 电机动作完成”和“耗材确实到位”分成不同证据。

## Goals / Non-Goals
- Goals:
  - 只在具备本次流程的新鲜证据时推进状态机。
  - 所有电机动作经过单一仲裁和统一的故障清理。
  - 未确认通道、未知传感器或打印机故障时优先保持暂停。
  - 让用户直接理解原始 AMS/HMS/打印错误正在表达的动作或故障。
- Non-Goals:
  - 不模拟打印机的自动重试、清错或“已出料”人工确认。
  - 不以关闭缠料、断料或堵料检测作为兼容手段。
  - 不把 P1/P1S 纳入本次硬件发布门槛。

## Decisions

### Decision: 协议解码为独立、可主机测试模块
AMS 状态按高 8 位主状态、低 8 位子步骤解析。模块保留原始整数，并返回 `main`、`sub`、中文标签和 `known`。已知主状态但未知子步骤以及完全未知主状态都不得回退成其他已知动作。

HMS 从 `attr` 高位和 `code` 低 16 位重建八位短码；已知故障返回中文原因与建议动作，未知非零错误返回十进制和十六进制原值。`print_error` 和严重 HMS 都能建立安全联锁。

### Decision: 命令接收与动作完成使用两层确认
G-code 先统一为 LF，并保证只有一个末尾换行，再由 ArduinoJson 序列化。每次发送生成递增 `sequence_id`，5 秒内只接受相同序列号的 MQTT 回执。

回执只证明打印机收到命令。退料完成由新鲜 `0x0104` 状态、完整电机回抽、稳定无料和 AMS 空闲共同证明；加热由实际喷嘴温度连续两次达标证明；进料由本次流程中的稳定“无料→有料”转换证明。

### Decision: 唯一电机控制器拥有所有方向 GPIO
手动正反转、自动退线、自动进线和微动辅助都通过同一非重入控制器。控制器记录 owner，并用作用域清理保证正常退出、超时、拒绝或紧急停止后所有电机引脚均为低电平。服务端在入队和实际执行前都检查通道、系统锁、流程阶段、故障与 owner。

微动输入采用 100 ms 稳定消抖和按下边沿触发；一次持续按住只产生一个 1 秒脉冲，稳定释放后才能再次触发。

### Decision: 耗材位置是原子三态且通道需要显式确认
打印机首次 `pushall` 返回前，传感器为 `unknown`。系统不推断当前通道。升级后 `extruder_confirmed=false`；有料时只有有效且已确认的持久化通道能进入就绪。无料时当前通道置 0。成功闭环装载会自动持久化并确认目标通道。

### Decision: 自动换料采用失败封闭状态机
固定阶段为触发、退料、退线、加热、进线和恢复。每个阶段保存 Top-AMS 自身阶段，同时读取打印机 AMS 动作。MQTT 超过 8 秒无数据、同序列回执超时、阶段超时、传感器不转换或严重打印机故障时，当前流程进入 `fault`、电机急停、目标通道不写入且不发送恢复命令。

退料成功后立刻把当前通道保存为 0，因此后续进料失败不会继续指向旧通道。故障后释放手动恢复所需的系统锁，但保持打印机暂停，由用户排障、重试并在打印机端恢复。

### Decision: 首料使用独立标记区间
普通换料继续使用热床目标 `1–8`；可选启动模板使用 `9–16` 表示首料通道 `1–8`。首料握手和普通换料复用相同闭环。若打印机已有料但真实通道未知，系统保持暂停并要求确认，不猜测通道。

### Decision: 独立实时状态消息补充诊断快照
保留现有五秒诊断快照和原始 `ams_status`，增加兼容字段，并仅在 AMS、故障或首料就绪变化时广播 `printer_operation_status`。页面分别渲染打印机动作和 Top-AMS 阶段。

## UI Direction
- Domain concepts: 料盘、通道、共享料路、耗材传感器、退料、回抽、加热、进料、冲刷、恢复。
- Color world: 继承 PCB 深灰、链路蓝、正常绿、等待琥珀和故障红。
- Signature: `AMS 原始码（中文动作）` 与六阶段料路时间轴同步，原始证据始终可见。
- Rejected defaults: 不用裸数字、彩虹状态徽章或新建通用卡片墙；实时状态嵌入现有设备诊断层级。

### Component checkpoint
- Intent: 用户站在打印机旁排查料路，需要立即知道打印机与 Top-AMS 各自在做什么、当前是否安全。
- Palette: 沿用现有蓝/绿/琥珀/红语义，颜色只强化文字状态。
- Depth: 使用边框和细微表面明度变化，不增加装饰性阴影。
- Typography: 系统中文字体解释动作，等宽数字呈现原始码、十六进制和时间。
- Spacing: 4px 基础单位，保持现有 8/12/16/24px 节奏。

## Risks / Trade-offs
- A1 mini 固件可能在极短时间内跳过某些子步骤；实时消息减少页面遗漏，但控制仍只依赖协议定义的必要证据。
- 打印机回执格式在不同固件可能缺少序列号；这种不确定性按安全失败处理，不自动恢复。
- 升级后首次需要用户确认当前通道，这是消除错误“默认通道 1”所需的兼容代价。

## Verification
- 主机与 Unity 测试覆盖解码、JSON、序列回执、新鲜状态、电机互斥、微动和所有状态机退出分支。
- 静态测试校验两个 G-code 模板的标记、暂停、安全前导和工具同步。
- 生成 4/6/8 通道页面资源并检查脚本语法、窄屏长中文、未知状态和非颜色信息。
- 发布前在 ESP-IDF 5.3.2 与 A1 mini 真机完成构建和故障注入验收。
