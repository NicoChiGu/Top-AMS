# Change: 稳定 A1 mini 耗材流程并可视化打印机状态

## Why
当前自动换料把打印机 AMS 原始码直接当作完成信号，并用固定延时驱动电机。多行 G-code 也没有经过标准 JSON 序列化，命令缺少唯一序列号和接收回执。启动或换料期间因此可能出现错误通道送料、退料未完成便进料、异常后仍恢复打印，并触发“料盘卡住”或“请检查是否有料挤出”等错误。

页面只显示原始整数，无法区分打印机正在执行的 AMS 步骤与 Top-AMS 自身阶段，也不会及时显示 HMS、打印错误、通道确认或 MQTT 陈旧状态。

## What Changes
- 标准化解码 AMS 主状态/子步骤、`print_error` 与 HMS，并向诊断快照和轻量实时消息提供中文含义。
- 用唯一序列号和 MQTT 同序列回执发送合法 JSON G-code；动作完成继续由新状态、实际喷嘴温度和耗材传感器闭环确认。
- 增加唯一电机仲裁、紧急停止、通道确认、微动消抖和不确定状态保护。
- 将自动退料、加热、进料与恢复改为失败即停止并保持暂停的闭环状态机。
- 默认保留官方启动流程；另提供基于官方 20260513 A1 mini 模板的显式可选自动首料模板。
- 修订普通换料 G-code 的安全前导和停靠顺序，保留打印机原有检测器与工具状态同步。
- 页面显示原始码、中文动作、故障处置和打印机/Top-AMS 双来源六阶段状态。

## Impact
- 影响的规范：`filament-flow-safety`、`printer-operation-status`、`a1mini-gcode-integration`、`runtime-diagnostics`
- 影响的代码：MQTT 解析、Bambu 协议、电机控制、换料触发器、自动/手动换料、持久化通道、诊断 WebSocket、Web 控制台、G-code 模板和测试
- 兼容性：保留 `diagnostics_snapshot.system.ams_status` 原始整数、现有配置键和官方默认启动流程；升级后新增的 `extruder_confirmed` 默认 `false`
- 安全性：任何严重打印机故障、MQTT 陈旧、回执超时或阶段超时都停止电机且不自动恢复打印
