# A1 mini 与 Top-AMS 通讯、切片选料及自动换料完整教程

> 适用代码基线：仓库提交 `9b82a35`（2026-07-21）  
> 适用对象：当前仓库的 ESP32-C3 固件、A1 mini、无原厂 AMS 的 Top-AMS 4/6/8 通道方案  
> 推荐换料模板：[A1mini换料_topams版本.gcode](./A1mini换料_topams版本.gcode)
>
> 只需要按界面操作的用户请直接阅读：[A1 mini + Top-AMS：Bambu Studio 完整用户操作流程](./A1mini_BambuStudio用户操作流程.md)

## 1. 先看结论

正常使用时，**不需要制作一个“逐个模型生成 G-code”的独立程序，也不建议默认使用后处理脚本修改成品 G-code**。

推荐方案是：

1. 把本仓库的 `A1mini换料_topams版本.gcode` 保存到一个单独的 A1 mini 打印机预设的“换料 G-code”中。
2. 在 Bambu Studio 或 OrcaSlicer 中正常添加耗材、涂色、分配零件和设置冲刷体积。
3. 切片器在每次换料时自动计算 `next_extruder`，模板再用：

   ```gcode
   M140 S{next_extruder + 1};EXT
   ```

   把切片器内部从 0 开始的耗材编号转换成 Top-AMS 从 1 开始的物理通道号。
4. `M400 U1` 让打印机进入暂停状态；ESP32 同时从 MQTT 收到目标热床温度和 `PAUSE` 状态，完成退料、进料并恢复打印。

后处理脚本只有在需要兼容不支持“换料 G-code”的切片器、批量审计大量外部 G-code，或需要维护多个打印机/切片器版本时才值得做。对当前项目而言，**一个只读的 G-code 校验器比自动改写脚本更安全**。

## 2. 当前实现到底怎样工作

### 2.1 通讯链路

Top-AMS 使用 A1 mini 的局域网 MQTTS 服务：

| 项目 | 当前代码值 |
| --- | --- |
| 服务器 | `mqtts://<打印机IP>:8883` |
| 用户名 | `bblp` |
| 密码 | 打印机显示的局域网访问码/MQTT 密码 |
| 状态订阅主题 | `device/<设备序列号>/report` |
| 指令发布主题 | `device/<设备序列号>/request` |

对应实现位于 [config.hpp](../main/config.hpp)、[espMQTT.hpp](../main/espMQTT.hpp) 和 [main.cpp](../main/main.cpp)。

ESP32 主要读取这些打印机状态：

- `bed_target_temper`：传递目标 Top-AMS 通道，也用于记忆正常热床目标温度。
- `gcode_state`：只有状态为 `PAUSE` 时才正式触发换料。
- `nozzle_temper`：实际喷嘴温度；必须连续两次达到目标温度减 5°C 才能进料。`nozzle_target_temper` 只作为目标值显示。
- `hw_switch_state`：打印机耗材检测三态的真实来源；首次 `pushall` 返回前保持“未知”。
- `ams_status`：按高 8 位主状态、低 8 位子步骤解码打印机动作，例如 `260=0x0104` 表示回抽当前耗材。
- `print_error` 与 `hms[]`：显示卡料、等待确认出料和其他打印机故障，并建立停机联锁。
- `sequence_id`：每条控制命令使用唯一递增值，只有同序列 MQTT 回执才表示打印机已接收。

### 2.2 通道编码

切片器内部的耗材/挤出机编号从 0 开始，用户和 Top-AMS 的通道从 1 开始：

| 切片器中显示 | `next_extruder` | 切片后标记 | Top-AMS 通道 |
| ---: | ---: | --- | ---: |
| 耗材 1 | 0 | `M140 S1;EXT` | 1 |
| 耗材 2 | 1 | `M140 S2;EXT` | 2 |
| 耗材 3 | 2 | `M140 S3;EXT` | 3 |
| … | … | … | … |
| 耗材 8 | 7 | `M140 S8;EXT` | 8 |

当前代码的边界要特别注意：

- **1–8** 是普通换料标记；可选自动首料模板使用独立的 **9–16** 标记并映射回通道 1–8。
- 4/6/8 通道构建会按真实构建数量在服务端校验；超出范围的普通或首料标记都会保持暂停并报错。
- 温度 17 不会被当前条件识别为通道。旧文档中的“1–17”不能按包含 17 的方式理解。

模板中的 `M140` 是由打印任务本身执行的通道标记。根据当前代码注释，A1/A1 mini 1.04 固件不可靠地接受通过 MQTT 下发的 `M140/M104`，所以 ESP32 恢复热床和设置热端时使用的是会等待温度的 `M190/M109`。不要在控制器代码里简单把它们替换成 `M140/M104`。

### 2.3 一次自动换料的完整时序

1. 切片文件执行 `M140 S{next_extruder + 1};EXT`。
2. 切片文件执行 `M400 U1`，A1 mini 暂停。
3. ESP32 收到 `bed_target_temper=目标通道` 和 `gcode_state=PAUSE`。
4. ESP32 记录当前 AMS 状态版本，发送经过 JSON 序列化的退料 G-code，并在 5 秒内等待同 `sequence_id` 回执。
5. 只等待本次命令之后的新 `AMS 260`；旧缓存不能满足条件。
6. 旧通道电机反转完整“退料时间”，随后 30 秒内必须同时确认传感器稳定无料和新的 AMS 空闲。成功后立刻把当前通道保存为 0。
7. ESP32 发送 `M109` 并等待**实际**喷嘴温度连续两次达到目标减 5°C，最长 300 秒。
8. ESP32 发送 `G1 E150 F500` 并等待同序列回执，然后驱动目标通道，要求出现本次流程的新鲜“无料→有料”稳定转换。
9. 传感器确认后额外保持最多 500 ms 完成交接，但总运行不超过“最大进料时间”，随后立即停机并确认目标通道。
10. 只有以上证据全部成立，ESP32 才恢复正常热床目标并提交恢复打印命令；切片文件随后执行冲刷、擦嘴和温度恢复逻辑。

任何命令回执超时、阶段超时、MQTT 超过 8 秒无数据、卡料或未确认出料都会停止电机、保留目标通道未写入并保持打印暂停；固件不会自动重试、清错或代替用户点击“继续”。

因此，**切片器负责决定何时换到哪一种料及冲刷多少；ESP32 负责真实的退线、选路、进线和恢复打印**。

## 3. 使用前的兼容性与安全要求

### 3.1 建议的软件/固件基线

- 本仓库留下的明确实机记录是 A1 mini 固件 `01.04.00.00`。
- 后续打印机固件可能修改 MQTT 鉴权、状态码或私有 G-code 行为。升级打印机固件前，应先保留可回退版本并重新做第 8 节的小模型测试。
- 推荐模板基于 A1 mini 官方换料 G-code `20251031` 修改。切片器大版本升级后必须重新切一个双材料测试件，确认模板变量仍能解析。
- 生产使用时，建议固定一套已验证的打印机固件、切片器版本和 Top-AMS 模板，不要在长时间多色打印前同时升级多个组件。

### 3.2 热床温度限制

- 不要把真实热床目标温度设为 1–16°C。
- 普通 PLA/PETG 常用热床目标温度通常高于该范围，但冷板、自定义材料或测试 G-code 仍需检查。
- 当前固件恢复的是自打印开始以来观察到的**最高热床目标温度**，不是每次换料前的最后一个目标值。多材料任务应使用相同或彼此兼容的热床温度；不要依赖换料时自动切换到更低的材料专用热床温度。
- 打印开始 G-code 应在第一次换料之前正常设置热床目标温度。默认 A1 mini 开始 G-code通常已经这样做。

### 3.3 网络与凭据安全

- A1 mini 与 ESP32 必须在同一个可信局域网。
- 建议在路由器中给打印机和 ESP32 做 DHCP 地址保留，避免重启后 IP 变化。
- Top-AMS Web 页面和局域网访问码不应暴露到互联网。
- 当前 Web 表单直接显示 MQTT 密码，操作时不要录屏或公开截图。

### 3.4 机械准备

- 所有料线必须顺畅通过分路器、PTFE 管和进退料机构。
- 待用料线的前端要预先推进到“配置的进料时间能够送入热端”的位置。
- 每条料线前端剪成利于进料的斜口，避免弯折和毛刺。
- 第一次调试必须有人看守，并能立即断开电机电源或暂停打印。

## 4. ESP32、网络和打印机连接

### 4.1 ESP32 配网

1. 刷入与实际硬件匹配的 4、6 或 8 通道固件。
2. 固件刷完后重启 ESP32。
3. 使用支持 SmartConfig 的配网工具；项目原说明使用微信小程序“一键配网”。
4. 在路由器客户端列表中找到 ESP32 的 IP。
5. 浏览器打开 `http://<ESP32-IP>/`。
6. 页面顶部应显示 ESP32 的 SSID、IP 和信号强度。建议 RSSI 保持在稳定范围；若经常断连，先改善路由器距离和 2.4 GHz 覆盖。

### 4.2 获取 A1 mini 参数

准备以下三项：

- **打印机 IP**：从 A1 mini 网络设置或路由器客户端列表查看。
- **设备序列号**：从打印机设备信息查看，也可在 Bambu Studio 的设备信息/固件页面查看。
- **局域网访问码/MQTT 密码**：从打印机的局域网模式相关页面查看。

不同固件版本的菜单文字可能略有变化。这里只读取局域网参数，不要求把打印机暴露到公网。

### 4.3 在 Top-AMS Web 中连接

1. 打开“网络配置”。
2. 填写打印机 IP、设备序列号和 MQTT 密码。
3. 点击“连接打印机”。
4. 转到“系统诊断”，检查：
   - MQTT 状态为已连接。
   - 最近收包时间持续更新。
   - 没有持续出现“数据超时”。
   - `hw_switch` 能随打印机耗材检测状态变化。
5. 如果在已经连接后修改了打印机 IP、密码或序列号，**保存后重启 ESP32**。当前程序不会可靠地热切换一个已经运行中的 MQTT 会话。

连接失败时依次检查：

1. 打印机和 ESP32 是否在同一网段。
2. 能否从电脑访问打印机 IP。
3. 序列号是否完整、没有空格。
4. 访问码是否为当前打印机显示的值。
5. 打印机固件是否改变了局域网鉴权要求。
6. 路由器是否启用了 AP 隔离、访客网络隔离或客户端隔离。

## 5. 先完成通道标定

不要直接拿正式多色模型试机。先在 Top-AMS Web 的“通道管理”逐一标定。

### 5.1 配置项含义

| Web 配置 | 当前作用 | 建议 |
| --- | --- | --- |
| 颜色 | 页面识别用 | 与切片器颜色保持一致，避免拿错 |
| 材料名称 | 页面识别用 | 写 PLA、PETG 等 |
| 进料时间 | 新通道最大进料时间，单位 ms | 传感器提前确认会提前停止；从短到长逐步增加 |
| 退料时间 | 旧通道电机反转时长，单位 ms | 以完全退出公共路径且不过卷为准 |
| 温度 | ESP32 执行退料/进料时使用的热端目标温度 | 按实际材料设置，不要盲目统一 250°C |
| 续料通道 | 已持久化但当前自动续料逻辑尚未启用 | 不要依赖它完成断料续料 |
| 输出方向 | 交换该通道正反转 GPIO | 只在系统空闲时调整 |
| 当前通道 | ESP32 认为热端中正在使用的物理通道 | 必须与现实完全一致 |
| 辅助进料 | 小绿点触发时让当前通道电机辅助正转 | 机械调试阶段可暂时关闭 |

代码默认值为：

- 温度：250°C。
- 进料时间：6000 ms。
- 退料时间：5000 ms。
- 辅助进料：开启。

这些只是启动默认值，不是所有结构和材料都适用。

### 5.2 校准电机方向

对每个实际通道重复：

1. 确认系统状态为空闲且没有其他电机运行。
2. 短时点击“正转”，确认料线朝热端方向移动。
3. 点击“反转”，确认料线朝料盘方向移动。
4. 如果相反，打开该通道的“反向输出”，再测试一次。
5. 不要通过交换网页中的通道编号来掩盖接线方向错误。

通道 7 会使用默认 LED GPIO；当前代码在第一次运行该通道时关闭 LED 控制。通道 8 的 GPIO18/19 可能受 USB 影响。使用这两个通道前必须根据实际开发板和供电方式做单独测试。

### 5.3 校准进退料时间

1. 将料线放到日常待机位置。
2. 先用较短时间测试，记录料线移动距离。
3. 调整退料时间，使旧料退出公共汇合路径，并留出安全余量，但不要一直拉扯料盘或把料头抽进难以取出的区域。
4. 调整最大进料时间，使新料能到达打印机耗材传感器；传感器确认后固件会提前停止并保持 500 ms 交接。
5. PLA、PETG、TPU 的摩擦和刚性差异较大，应按通道实际材料标定。
6. TPU 等柔性材料必须显著降低速度风险并加强人工看守；当前固定时间控制没有堵转或打滑闭环。

### 5.4 设置真实“当前通道”

这是当前版本最关键的人工步骤。

- 如果热端中是通道 3 的料，Web 中“当前通道”必须选择“通道 3”。
- 如果热端无料，选择“无耗材”。
- ESP32 启动时若检测到有料但通道未确认，会显示“请确认当前通道”并禁止辅助送料，绝不会默认认为通道 1。
- 默认官方启动模式不会把切片器选择的“首个打印耗材”自动同步到 ESP32；可选首料模板会通过独立的 `9–16` 标记同步目标，但已有料且真实通道未知时仍要求人工确认。

设置错误会让固件反转错误的旧通道，严重时会出现两条料同时进入公共路径。

## 6. 在切片器中安装 Top-AMS 换料模板

### 6.0 当前仓库是否需要替换启动 G-code

**默认不需要。推荐先使用官方启动 G-code + 人工预装并确认首料；需要自动首料时再显式使用仓库的 `20260513` 可选模板。**

原因和边界：

- 默认官方启动模式不执行 Top-AMS 自动选料，用户需要提前装好首个耗材并在 Web 中确认正确的“当前通道”。
- [A1mini启动_topams首料_20260513.gcode](./A1mini启动_topams首料_20260513.gcode) 只在官方模板原有 `M620 M` 前加入 `9–16` 首料标记、暂停和热床恢复。它复用普通换料闭环：无料时装载、其他已知通道先退换料、未知通道保持暂停。
- 仓库中的 `A1mini快速启动.gcode` 是第三方快速启动脚本，仍包含原厂 `M620/T/M621` 启动段，没有 Top-AMS 的 `;EXT + M400 U1` 首料触发；它不是本项目的专用启动模板。
- 其他 Top-AMS 项目如果提供成对的启动与换料 G-code，可能通过启动代码自动处理首料。那属于另一套工作流，不能与本仓库模板交叉混用。
- 如果已经改过启动 G-code，应从当前 Bambu Studio 的官方 A1 mini 系统预设重新复制一个用户预设，然后只替换换料 G-code。

### 6.1 选择正确文件

| 仓库文件 | 用途 | 是否推荐用于当前 Top-AMS |
| --- | --- | --- |
| `A1mini换料_topams版本.gcode` | 无原厂 AMS，外部通道通知、暂停、自动恢复、完整冲刷 | **推荐** |
| `A1mini换料.gcode` | 较早的精简/减量冲刷版本 | 仅兼容性测试，不作为默认 |
| `A1mini换料_增强版.gcode` | 在官方 AMS 流程上加热床通知，仍保留 AMS 专用换料动作 | 无原厂 AMS 时不推荐 |
| `A1mini换料_原版.gcode` | 官方逻辑参考 | 不可直接驱动 Top-AMS |
| `A1mini启动_原版.gcode` | 官方 `20260513` 启动 G-code 参考 | 默认工作流 |
| `A1mini启动_topams首料_20260513.gcode` | 官方基线 + 三行首料握手 | 可选，闭环换料验证后使用 |
| `A1mini快速启动.gcode` | 第三方快速启动方案 | 非 Top-AMS 必需项，不要和换料改造同时首次测试 |

### 6.2 Bambu Studio

不同版本的中文名称可能略有差异，核心路径是：

1. 切换到“高级/专家”设置模式。
2. 选择 A1 mini 和实际喷嘴直径。
3. 复制/另存官方打印机预设，命名为类似 `A1 mini 0.4 - Top-AMS`。不要直接覆盖系统预设。
4. 打开打印机预设编辑窗口。
5. 进入“机器 G-code / Machine G-code”。
6. 找到“换料 G-code / Change filament G-code”。
7. 先把原内容另存为备份。
8. 用文本编辑器打开 [A1mini换料_topams版本.gcode](./A1mini换料_topams版本.gcode)，复制**全部内容**并替换该字段。
9. 保存新的打印机预设。

不要只把 `M140` 和 `M400 U1` 两行简单加到官方 AMS 换料代码前面。恢复后如果继续执行未改造的 `M620/T/M621` 换料链路，可能再次等待不存在的原厂 AMS。

默认 Top-AMS 不要求替换“开始 G-code”。保留当前切片器随 A1 mini 预设提供的官方内容，并按照独立的[纯用户操作流程](./A1mini_BambuStudio用户操作流程.md)完成首料准备。可选自动首料必须使用仓库明确版本化的 `20260513` 文件，不要手工拼接其他启动脚本。

### 6.3 OrcaSlicer

1. 复制一个 A1 mini 打印机预设。
2. 打开 `Printer Settings > Machine G-code > Change filament G-code`。
3. 粘贴推荐模板的全部内容。
4. 如果该版本提供 `Multimaterial > Manual Filament Change`，使用无原厂 AMS 的手动/外部换料模式。
5. 保存为单独的 Top-AMS 预设。

OrcaSlicer 官方文档确认“Change filament G-code”会在耗材变化时插入，并包含工具切换触发点。无论使用哪种切片器，模板能否解析都必须以一次实际切片结果为准。

## 7. 切片选料、涂色和冲刷配置

### 7.1 建立物理通道与耗材槽的一一对应

切片器左侧的耗材顺序必须固定映射到 Top-AMS：

| 切片器耗材 | 物理通道 |
| --- | --- |
| 耗材 1 | 通道 1 |
| 耗材 2 | 通道 2 |
| … | … |
| 耗材 N | 通道 N |

建议：

- 切片器颜色、Top-AMS Web 颜色和实际料盘标签使用同一颜色。
- 不要为了减少列表长度临时删除中间槽位。例如实际使用通道 1 和通道 4 时，仍应让目标材料保持为“耗材 4”，不能把它临时改成“耗材 2”。
- 当前系统没有 RFID/AMS 槽位自动同步，换料映射完全依赖这一顺序。

### 7.2 给模型分配耗材

可以使用切片器原生的任何方式：

- 给整个对象指定耗材。
- 给零件/部件指定耗材。
- 使用颜色绘制工具。
- 给支撑主体或支撑接触面指定耗材。
- 在预览层条上插入换色。

切片后进入“预览”，确认每个颜色区域使用了预期耗材编号，并检查第一层实际先使用哪一个耗材。

### 7.3 打印前准备首个耗材

使用默认官方开始 G-code 时，固件不会根据切片器自动选择第一通道，因此必须：

1. 在切片预览中确认最先打印的耗材编号。
2. 通过 Top-AMS Web 的“装载”按钮加载对应物理通道，或者手动预装该料。
3. 再次确认 Web 的“当前通道”与热端内真实料线一致。
4. 确认其余料线位于各自标定的待机位置。

例如，首层先用“耗材 3”，就要先装载物理通道 3，并把当前通道设置为 3，不能依赖启动时默认的通道 1。

### 7.4 冲刷体积

推荐模板保留了切片器的完整 `flush_length_1` 至 `flush_length_4` 逻辑，因此切片器中的冲刷矩阵/冲刷体积会生效。

调试原则：

1. 首次使用先从切片器默认或偏保守的冲刷体积开始。
2. Top-AMS 在暂停期间会发送 `G1 E150 F500` 辅助进料，其中一部分挤出距离用于把新料带到热端；恢复后模板还会执行切片器冲刷。
3. 如果废料过多，在确认新颜色已经稳定后逐步降低对应颜色转换的冲刷量。
4. 如果混色、欠挤出或新料尚未稳定，增加冲刷量或进料时间。
5. 深色转浅色通常需要比浅色转深色更多冲刷。
6. 不要为了省料直接把所有转换设为极低值。先用小测试件建立自己的材料组合矩阵。

## 8. 切片后必须检查 G-code

第一次使用新预设、升级切片器、修改模板或增加通道后，都要导出/查看切片结果。

### 8.1 检查通道标记

搜索：

```text
;EXT
```

每个真实换料点都应出现类似：

```gcode
M140 S2;EXT
...
M400 U1
```

这表示目标物理通道 2。注意开始 G-code 中正常的 `M140 S60` 不是通道标记，只有带 `;EXT` 的低温命令用于 Top-AMS。

### 8.2 检查内容

- `M140 Sx;EXT` 中的 `x` 必须处于本机实际通道范围。
- 标记之后必须有 `M400 U1` 暂停点。
- 同一次换料不能重复出现两个 `;EXT` 标记。
- 不应在暂停前执行会等待原厂 AMS 的完整工具切换链路。
- 切片器不能报告未知变量或自定义 G-code 解析错误。
- 单色模型通常不会出现 `;EXT`，这是正常的。

### 8.3 为什么不直接自动后处理

最终 G-code 中还有开始 G-code 的正常热床命令、切片器生成的工具切换、3MF 元数据以及不同版本的占位符。盲目按 `T0/T1` 搜索替换容易：

- 重复插入通道信号。
- 修改模板内部用于抑制 AMS 等待的 `T[next_extruder]`。
- 把开始阶段或校准阶段的命令误判为换料。
- 破坏打包后的 3MF/G-code 结构。

因此当前应优先在切片器的“换料 G-code”阶段生成正确内容，而不是事后修补。

## 9. 第一次联调：只用小型双色测试

准备一个换色次数少、几分钟即可到达换料点的双色模型。

### 9.1 打印前检查单

- [ ] 打印机固件和切片器版本已记录。
- [ ] ESP32 Wi-Fi 稳定，MQTT 已连接，最近收包持续更新。
- [ ] 通道 1、2 的正反转方向正确。
- [ ] 进料时间、退料时间和材料温度已初步标定。
- [ ] 切片器耗材 1、2 对应物理通道 1、2。
- [ ] 热端内已经装好首个耗材。
- [ ] Web“当前通道”与热端内真实通道一致。
- [ ] G-code 中目标换料点存在 `M140 S2;EXT` 和 `M400 U1`。
- [ ] 真实热床目标温度不在 1–16°C。
- [ ] 操作人员在现场，料路和电机可见。

### 9.2 正常现象

到换料点时应依次看到：

1. A1 mini 暂停。
2. 系统诊断出现换料触发，时间轴显示目标通道。
3. 热床目标温度短暂承担通道信号，然后恢复正常温度。
4. 旧通道退料。
5. 旧通道电机反转退出公共路径。
6. 新通道电机正转送入新料。
7. Web“当前通道”更新。
8. A1 mini 自动恢复。
9. 切片器生成的冲刷和擦嘴流程继续执行。
10. 模型以新颜色继续打印。

通过双色测试后，再逐步增加换料次数、颜色数和打印时长。

## 10. 常见问题

### 10.1 打印机暂停，但 Top-AMS 完全不动作

检查：

- MQTT 是否连接。
- 最近收包是否超过 8 秒未更新。
- 序列号和订阅主题是否正确。
- `;EXT` 标记是否在 `M400 U1` 之前。
- 标记值是否在 1–8 内。
- 打印机报告的状态是否为 `PAUSE`。

### 10.2 Top-AMS 收到温度，但不触发换料

当前代码同时要求：

```text
bed_target_temper 在 1–16
并且 gcode_state == PAUSE
```

只有 `M140 Sx`、没有 `M400 U1` 不足以触发。

### 10.3 一直停在“等待退料”

固件最长等待 120 秒获取 `ams_status=260`。常见原因：

- 打印机固件不再返回相同状态码。
- `M620 S255 / T255 / M621 S255` 没有被当前固件接受。
- MQTT 数据已经中断。
- 打印机自身存在退料、切刀或耗材检测异常。

不要在不了解料路状态时连续点击恢复。先导出 Web 诊断日志并检查打印机屏幕错误。

### 10.4 进料后仍然没出料

- 增加目标通道进料时间。
- 把待机料头预先推进得更靠近公共入口。
- 检查新料是否真的进入热端齿轮。
- 检查通道材料温度是否合理。
- 检查 PTFE 接头、三通和料头是否卡住。
- 检查 `G1 E150 F500` 是否被打印机接受。

### 10.5 电机打齿或持续顶料

- 减少进料时间。
- 检查辅助进料是否因小绿点持续触发而反复运行。
- 检查当前通道是否正确。
- 检查料路阻力和电机方向。
- 不要仅靠延长时间解决机械卡阻。

### 10.6 退错通道或两条料相撞

立即停止并检查：

- Web“当前通道”是否与换料前热端内的料一致。
- 切片器耗材顺序是否与物理通道一一对应。
- 是否删除了中间耗材槽，导致后续编号前移。
- 电机输出方向是否设置错误。

### 10.7 热床温度恢复不正确

当前固件使用打印期间观察到的最高正常热床目标温度。检查：

- 开始 G-code 是否在第一次换料前设置了正常热床目标温度。
- 是否混用了不同热床温度的材料。
- 是否有其他自定义 G-code 在打印中设置了更高热床温度。
- 打印结束时是否正常把热床目标设为 0，以重置记录。

### 10.8 单色正常，多色切片没有换料标记

- 模型可能仍全部分配给同一个耗材。
- 涂色结果可能没有形成实际的挤出路径。
- 换料模板可能保存在另一个打印机预设中。
- 当前切片任务可能重新切回了官方 A1 mini 预设。

### 10.9 修改 MQTT 参数后仍连接旧打印机

当前运行中的 MQTT 客户端不会可靠地热切换到新参数。保存新参数后重启 ESP32，再检查诊断页。

## 11. 是否需要 G-code 生成器或后处理脚本

### 11.1 当前不需要“专门生成器”

切片器已经负责：

- 模型切片。
- 多材料路径规划。
- 计算新旧耗材编号。
- 计算冲刷体积。
- 生成擦嘴、切屎、温度和运动命令。

重新写一个生成器等于重复实现切片器的重要部分，成本和风险都很高。

### 11.2 当前不建议自动改写式后处理

当前模板依赖切片阶段变量：

- `next_extruder`
- `previous_extruder`
- `flush_length_*`
- `flush_temperatures`
- `new_filament_temp`
- `retract_length_toolchange`

这些信息在模板展开后部分丢失或已转换，后处理脚本很难像切片器本身一样准确理解全部上下文。切片器版本变化还可能导致重复注入和误匹配。

### 11.3 值得做的是“只读校验器”

如果后续要降低用户配置错误，建议先做一个不会修改文件的校验工具，只报告：

- 是否找到 `;EXT`。
- 每个 `;EXT` 后是否存在 `M400 U1`。
- 通道是否超过指定的 4/6/8 通道上限。
- 是否有连续重复信号。
- 是否可能在暂停前出现未隔离的 AMS 工具切换。
- 换料次数和目标通道序列。
- 是否存在真实热床目标 1–16°C 的可疑命令。

校验器失败时阻止正式打印，由用户回到切片器修正；不要让脚本静默修改成品 G-code。

### 11.4 以后何时再做后处理

只有满足以下需求时再立项：

- 需要支持没有“Change filament G-code”入口的切片器。
- 要把第三方已经切好的普通多色 G-code 转成 Top-AMS 格式。
- 要批量迁移大量固定版本的文件，并有回归样本。
- 能明确限制输入格式为纯文本 G-code，而不是任意 3MF/BGCode。
- 已有自动化测试验证每次换料的插入位置、通道和暂停顺序。

对普通用户，更优先的交付物是：

1. 当前这份教程。
2. 一个经过版本标记的标准换料模板。
3. 一个可导入的 Top-AMS 打印机预设/配置包。
4. 一个只读校验器。
5. 最后才是自动改写式后处理。

## 12. 升级、回退与问题反馈

升级任一组件前记录：

- A1 mini 固件版本。
- Bambu Studio/OrcaSlicer 版本。
- Top-AMS 固件提交或发布版本。
- 使用的换料 G-code 文件及修改。
- 4/6/8 通道构建类型。
- 各通道进退料时间和温度。

回退方法：

1. 在切片器中切回保存的官方 A1 mini 打印机预设，或恢复之前备份的换料 G-code。
2. 使用单色小模型确认打印机基础功能。
3. 再恢复已验证的 Top-AMS 预设和固件组合。

提交问题时建议附上：

- 切片后的换料点附近 G-code。
- Web“系统诊断”导出的 UTF-8 日志。
- 最近一次换料六阶段时间轴。
- 打印机屏幕错误。
- 实际当前通道、目标通道和小绿点状态。
